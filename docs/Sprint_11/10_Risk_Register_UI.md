# Sprint 11 — UI Implementation Risk Register

| ID | Risk | Impact | Probability | Mitigation | Verification |
|---|---|---|---|---|---|
| R-01 | **Global token retune breaks every page at once.** `globals.css` is consumed by all 15 routes; `--primary` changing from near-black to violet will alter every `bg-primary`/`text-primary` usage instantly. | **Critical** — whole app visually regresses | High | Day 01 changes tokens **additively** and retunes only values, keeping all token *names*. Existing hardcoded utilities (`bg-blue-600`) are deliberately **not** mass-replaced, so unstyled-by-token pages keep their current look until their own day. | Day 01 requires visiting **all 15 routes** and confirming each still renders coherently (not necessarily final-design) with no layout collapse. |
| R-02 | **Shared shell edits (`Sidebar`, `Navbar`, `dashboard/layout.tsx`) regress all 8 authenticated pages.** | **Critical** | High | Treat shell as its own day (01) with an explicit all-route regression pass. Container max-width change is called out as high blast radius and must be verified page by page, especially the 4-column pages. | Day 01 checklist: every authenticated route loads, sidebar navigates correctly, no horizontal overflow at 1280/1440/1920. |
| R-03 | **Fabricated data ships to production.** The reference shows populated metrics (12 applications, 47 profile views, 92% match) with no data source. | **High** — the product lies to users | **High** (it is the path of least resistance to "match the screenshot") | Every day has a mandatory Error/Empty/Loading section; `05_Job_Search_Boundary.md` and `07_Future_Sprint_Boundaries.md` enumerate exactly which metrics have no source. Explicit rule: empty state, never example data. | Per-day QA step: with a **fresh account that has no data**, every card shows an empty state and no invented number appears anywhere. |
| R-04 | **Existing functionality removed to match a screenshot.** Highest-risk instance: deleting `JDMatcherPanel` because the reference shows job listings instead. | **High** | Medium | `05_Job_Search_Boundary.md` makes preserving `JDMatcherPanel` non-negotiable. Every day lists "Existing Functionality To Preserve" and "Files That Must NOT Be Changed". | Per-day functional QA exercises the page's real interactions; Day 09 specifically re-tests JD matching end-to-end. |
| R-05 | **Font loading changes shift every layout.** Currently no font loads (stubbed) — the browser is using a default. Loading a real geometric sans will change every metric. | **High** | **Certain** (it is the intended change) | Land it on Day 01, before any page is pixel-tuned, so no per-page tuning is done against the wrong font. | Day 01: all 15 routes checked for text overflow, clipped buttons, and wrapped nav labels after the font lands. |
| R-06 | **Two conflicting ATS designs implemented, or the wrong one chosen.** | Medium — wasted day, rework | Medium | `03_Reference_Conflicts.md` C-01 marks it **BLOCKING**; Day 08 is written against Variant B with A's deltas listed. | Owner confirmation obtained **before** Day 08 starts. |
| R-07 | **Hero illustration cannot be produced to match the reference**, so a random stock image is substituted. | Medium — landing page feels off-brand | Medium | `04_Asset_and_Image_Requirements.md` A-04 gives a full generation brief. Explicit rule: no stock substitution, no unrelated placeholder. If generation fails, ship a tasteful gradient/geometric composition and flag it — do not ship an unrelated photo. | Day 02 visual comparison; asset reviewed against the A-04 brief before integration. |
| R-08 | **Missing UI primitives cause ad-hoc duplication** (five different chip implementations, three donuts). | Medium — long-term maintenance cost | Medium-High | Day 01 front-loads the 18 shared primitives from `09_Shared_Component_Strategy.md`. | Code review on each later day: does it import from `components/common/` rather than re-implementing? |
| R-09 | **Responsive breakage** — no mobile reference exists, and the 4-column layouts (Builder, ATS B) have nowhere to go on a phone. | High | High | Each day specifies desktop/tablet/mobile behaviour conservatively; 4-column pages collapse to a documented stack order rather than shrinking. | Every day tests 1440 / 1024 / 768 / 390 widths with no horizontal scroll. |
| R-10 | **Dark mode silently breaks** — the reference is light-only, so dark values get neglected. | Medium — an existing, working feature degrades | High | C-05: dark mode must be preserved; Day 01 defines `.dark` values for every new token. | Every day toggles dark mode and checks contrast and legibility. |
| R-11 | **Accessibility regressions** — the reference's low-contrast captions, tinted-on-tinted chips, and icon-only buttons are all easy to ship inaccessibly. | High | Medium-High | Every day has an Accessibility QA section: focus rings, labels on all inputs, `aria-label` on icon-only controls, 4.5:1 body contrast, keyboard operability of tabs/chips/toggles. | Per-day keyboard-only pass + contrast check on new text/background pairs. |
| R-12 | **Root redirect change locks out or misroutes users.** Day 02 changes unauthenticated `/` behaviour. | High — worst case, broken entry to the app | Low-Medium | Only unauthenticated behaviour changes; authenticated → `/dashboard/agent` is preserved verbatim. Logged with rollback in `06_Decision_Log_UI.md`. | Day 02: test logged-out (→ landing), logged-in (→ agent), and mid-session-expiry cases. |
| R-13 | **Scope creep into future sprints** because the UI now displays Upgrade/Roadmap/Tracker affordances. | High — unplanned work, unplanned risk | Medium | `07_Future_Sprint_Boundaries.md` enumerates every depicted-but-deferred feature with an explicit "this sprint / future sprint" split; hard rule: no new routes. | Per-day check: `package.json` unchanged (except a logged Day 05 charting decision), no new route folders, no `app/api` or `agent-service` edits. |
| R-14 | **Unnecessary dependency added** (chart library, icon pack, animation library). | Medium — bundle and maintenance cost | Medium | `radix-ui`, `framer-motion`, `lucide-react` already cover almost everything. Only genuine candidate is charting (Day 05), which must be a logged decision with a hand-rolled-SVG alternative considered. | `git diff package.json` reviewed on every day; must be empty unless logged. |
| R-15 | **Performance regression from the hero image** (LCP) and from font loading (CLS). | Medium | Medium | A-04 specifies WebP + 1x/2x + `next/image` with `priority` and `sizes`; fonts loaded via `next/font` (self-hosted, `display: swap`). | Day 02: Lighthouse/DevTools check of LCP and CLS on `/`. |
| R-16 | **Company logo trademark exposure** if real Google/Microsoft/Amazon marks are bundled or AI-generated. | Medium — legal/brand | Medium | A-07: monogram `CompanyAvatar` fallback; real logos only from an authorized source, flagged to the owner. | Day 09: confirm no third-party logo files were added to `public/`. |
| R-17 | **Fake testimonial / social proof** — a named endorsement and "500K+ users" claim that may not be true. | Medium — credibility and potentially regulatory | Medium | A-09 raises this as a **blocking content question for the owner** on Day 02. Documentation mode does not resolve it. | Day 02: owner has confirmed the copy and the attribution before the page ships. |
| R-18 | **Cover Letters / Career Coach / History / Settings have no reference**, so Days 11–14 drift into invention. | Medium | Medium | Days 11–14 are scoped to token/primitive alignment only: no new sections, no invented layouts. Owner asked to supply designs if they exist. | Per-day diff review: only styling and primitive swaps, no structural or content additions. |
| R-19 | **Console/network errors introduced by new components** (missing assets 404ing, `next/image` misconfiguration). | Medium | Medium | Every day's verification includes an explicit console-clean and network-clean check. | DevTools Console and Network tabs must be clear of new errors/404s. |
| R-20 | **Existing test suites break** from component or markup changes (several agent tests assert on component behaviour). | Medium | Medium | Every day runs the full existing suite; shell/primitive changes on Day 01 are the most likely trigger. | `npm test` + `npm run build` green on every day; Python suites unaffected but spot-checked on Day 01. |
